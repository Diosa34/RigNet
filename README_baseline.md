## [models/supplemental_layers/pytorch_chamfer_dist.py](./models/supplemental_layers/pytorch_chamfer_dist.py)  

Добавлены функции:

* point_to_segment_distance(...)

Расстояние от сустава, до ближайшей точки кости.

* segment_to_segment_distance(...)

Численное приближение расстояния между костями через дискретизацию.

* compute_cd_j2j(...)

Вызывается существующая функция chamfer_distance_with_average(...)

* compute_cd_j2b_full(...)

Предсказанные суставы сравниваются со всеми точками всех GT-костей, а GT-суставы — со всеми точками всех предсказанных костей.

Суставы немного смещены, но всё ещё находятся непосредственно возле соответствующих костей: J2J может показать заметную ошибку, но J2B останется маленьким.

Суставы сами по себе могут быть сравнительно близки к каким-то GT-точкам, но костная структура проходит совсем в другом месте: J2J маленькое, а J2B — большое.

Метрика при этом не показывает, какая именно кость оказалась ближайшей.

* compute_cd_b2b(...)

Среднее расстояние от предсказанных костей до ближайших GT-костей.

* compute_iou(...)

Аналог объединения множеств:

IoU=$\frac{matched​}{∣pred∣+∣gt∣−matched}$​

То есть:

1 → полное совпадение;
0 → совпадений нет.

tolerance вычисляется как 5% от среднего радиуса расположения суставов относительно начала координат, если не задан.

Используется Hungarian algorithm / задача о назначениях, ищет такое соответствие predicted joints и GT joints, чтобы суммарная стоимость расстояний была минимальной.

* compute_precision_recall(...)

TP - счётчик правильных совпадений.

FP=∣Pred∣−TP - predicted joints, которыбыли предсказаны неверно

FN=∣GT∣−TP - GT joints, которые не были верно предсказаны

Precision=$\frac{TP}{TP+FP}$​ - какая доля предсказанных суставов оказалась правильной

Recall=$\frac{TP}{TP+FN}$ - какую долю настоящих суставов удалось найти

## [./run_joint_pretrain.py](./run_joint_pretrain.py)  

* train(...)

Исправлена нормализация loss, теперь деление на реальное количество графов в батче.

* test(...)

Для jointnet:
- вычисляются метрики chamfer (J2J), mean_joint_error (средняя ошибка, для каждого GT joint насколько далеко находится ближайший предсказанный joint, например, 0.0162 ≈ 1.62% размера объекта), recall_0.01, recall_0.025, recall_0.05 (какая доля истинных суставов имеет ближайшее предсказание на расстоянии меньше n / 100 ≈ n% размера модели)
В оригинальном пайплайне RigNet меши нормализованы в единичный куб, поэтому, интерпретируем результаты относительно размера модели. 
- исправлена нормализация loss, как в train(...)

Для masknet:
- собираются предсказанные вероятности и истинные labels;
- вычисляются precision, recall, f1, pr_auc (Average Precision, используемая как PR-AUC-подобная метрика).

Теперь возвращает значение всех метрик, соответствующих сети, в том числе loss.

## [./run_skinning.py](./run_skinning.py) 

Разрешение пути к файлу инкапсулировано в get_bone_names(...), теперь использование функции чище.

* test(...)

1) После применения loss_mask prediction теперь повторно нормализуется, запрещённые кости удаляются, а их веса перераспределяются между оставшимися костями так, чтобы сумма весов снова была равна 1.
2) Prediction и GT теперь явно разворачиваются из K nearest bones в полный вектор всех костей.

Раньше в test() сравнение происходило в пространстве K ближайших костей, теперь значения сначала раскладываются по реальным индексам костей, и уже полный вектор сравнивается с GT.

3) Полные prediction и GT ещё раз нормализуются.
4) Появился отдельный threshold для определения active bones для подсчёта метрик, выбирается по F1, по умолчанию 1e-4.
5) При финальном сохранении всё ещё применяется старый relative threshold 0.5 = 50% от максимального веса.

Вычисляются L1, avg_dist (из L2), max_dist (из L2), precision, recall.

## [./mst_generate.py](./mst_generate.py)  

Изменения структуры Data:
- исходный NumPy-массив передаётся отдельно
- теперь явно выделены как атрибуты пары: расстояние между joints, доля bone внутри объекта, label
- Data теперь явно поддерживает batch-входные данные для joints и пар (на данный момент не используется)
- data.y сохраняет совместимый с размером mesh массив, а data.joints — настоящие predicted joints
- joints расширяется по принципу «повторить joints достаточное число раз, чтобы получить минимум len(mesh_v) элементов»;

Изменения после генерации skeleton:
- парсятся GT-rig`s и восстанавливается дерево, затем сравнивается геометрия joints/bones, topology дерева с predicted для вычисления метрик
- если нет GT edges или predicted edges, метрики для конкретной модели пропускаются
- IoU / Precision / Recall используют относительный, зависящий от масштаба объекта порог совпадения joint
```
scale = mean(||gt_joint||)
tolerance = 0.05 * scale
```
- CD-J2J, CD-J2B, CD-B2B, Tree Edit Distance
